# Ubilling scipts for debian NAS
це набір оптимізованих системних скриптів для Debian Linux, що забезпечують інтеграцію білінгової системи Ubilling з ```rscriptd```, а також автоматизують шейпінг трафіку, створення ізольованих хеш‑черг tc, динамічну взаємодію з користувацькими сесіями та базову мережеву безпеку.

Скрипти призначені для використання на NAS/серверних системах, які виконують роль BRAS/BNG (Broadband Remote Access Server) з встановленими ```nftables``` та ```tc``` (Traffic Control).

## Для чого ці скрипти

- автоматичне застосування шейпінгу при підключенні абонента (```OnConnect```) та зняття обмежень при відключенні (```OnDisconnect```)
- динамічна робота зі швидкостями, тарифами та параметрами, що надає Ubilling через ```rscriptd```
- побудова масштабованої структури tc‑черг на хешах
- файрвол з базовими захисними політиками
- тюнінг мережевого стеку Linux для мінімальної затримки та коректної роботи шейпера
- підтримка великої кількості абонентів без зниження продуктивності

### Як працює шейпінг та хеш таблиці tc

Для формування черг ми використовуємо Linux ```tc``` (Traffic Control) з архітектурою hashing classes:

 - Верхній клас — корінь HTB
 - Другий рівень — хеш‑таблиці (які дозволяють працювати з тисячами черг)
 - Третій рівень — індивідуальні класи для кожного IP

#### Принцип роботи  хеш таблиць tc:

1) Скрипт отримує мережу / VLAN, до якої належить абонент.
   - хеш визначаэться за 3-м октетом підмережі, тому перші 2 октети вказуються вручну і в подальшому автоматично не оброблюються.
2) Визначає унікальний хеш‑бакет для IP.
   - хеш визначаэться автоматично за 4-м октетом IP
3) Створює клас зі швидкостями абонента (ingress/egress).
4) Додає фільтр tc, який направляє пакети IP → відповідний хеш.

#### Блок‑схема роботи хеш‑структури tc:
```
[Абонентський IP]
        |
        v
[Hash bucket] ---> [HTB class] ---> [Rate / Ceil] ---> [qdisc]
```

### Що роблять скрипти:

#### ```OnConnect```

Файл: ```/etc/rscriptd/OnConnect```

- Обчислює хеш для ```tc```
- Створює ```tc class```, ```tc filter```, ```tc qdisc``` - дочірній
- додає користувача до ```set allowed_clients``` nftables
  - перевірити доданих клієнтов можна перевірити командою: ```nft list set inet firewall allowed_clients```

#### ```OnDisconnect```

Файл: ```/etc/rscriptd/OnDisconnect```

Видаляє:
- ```tc class```
- ```tc qdisc```
- ```tc filter```
- видаляє користувача з ```set allowed_clients``` nftables

#### Скрипти повністю сумісні з rscriptd та логікою Ubilling.

### Тюнінг системи

Для правильної роботи шейпінгу застосовуються:
- ```sysctl``` оптимізації мережевої черги
- збільшення буферів
- вимкнення зайвих offload (GRO/LRO/TSO)
- вручну налаштовані txqueuelen та qdisc на фізичних інтерфейсах

Файл тюнінгу знаходиться в ```/etc/sysctl.conf``` у проєкті.

### Firewall

Файл /etc/furrywall містить:
- Антиспуфінг правила
- Блокування неавторизованих IP
- Захист від фрагментації/мальформації пакетів
- Дозвіл/заборона трафіку після авторизації
- Файрвол повністю інтегрований із системою tc та OnConnect/OnDisconnect.

## ОБОВʼЯЗКОВО: необхідно вручну перезібрати ядро Linux з ```HZ=1000```

Для коректної роботи HTB + hash‑черг і точного таймінгу планувальника потрібна частота системного таймера ```HZ = 1000```. 

Стандартні ядра Debian часто використовують HZ=250 або HZ=300, що призводить до:
- неправильного rate shaping;
- плаваючих швидкостей;
- затримок у qdisc.

Інструкція: як зібрати кастомне ядро Linux з **HZ=1000**

- Встановити залежності:
```
apt install build-essential libncurses-dev libssl-dev bc flex bison dwarves rsync
```

- Завантажити вихідний код ядра:
```
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.12.tar.xz
 tar xf linux-6.12.tar.xz
cd linux-6.12
```

Скопіювати конфіг з поточного ядра:
```
cp -v /boot/config-$(uname -r) .config
```

Відкрити меню конфігурації:
```
make menuconfig
```

Перейти: 
```General setup → Timers subsystem → Timer frequency```

Встановити: **1000 HZ**

Зібрати ядро:
```
make -j$(nproc)
make modules_install
make install
````

Оновити GRUB та перезавантажитися:
```
update-grub
reboot
```

Після перезавантаження перевірити:
```
zcat /proc/config.gz | grep HZ=
```

Очікувано: **CONFIG_HZ_1000=y** та **CONFIG_HZ=1000**
